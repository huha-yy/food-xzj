# 基于SpringBoot的大学生校内美食评价系统 - 系统架构设计文档

## 一、架构概述

### 1.1 架构模式
本项目采用 **前后端分离架构**（B/S架构），前端和后端独立部署，通过HTTP协议进行数据交互。

- **前端**：React 18.x + Vite 5.x + Ant Design 5.x
- **后端**：SpringBoot 3.x + MyBatis-Plus 3.5.x
- **通信协议**：RESTful API + JSON
- **部署方式**：本地运行，单体应用（非微服务）

### 1.2 架构图

```
┌─────────────────────────────────────────────────────────┐
│                      用户浏览器                          │
│                   (React + Ant Design)                  │
└────────────────────────┬────────────────────────────────┘
                         │ HTTP/HTTPS
                         ↓
┌─────────────────────────────────────────────────────────┐
│                   SpringBoot后端                         │
├─────────────────────────────────────────────────────────┤
│  控制层（Controller）   │  安全层（Security + JWT）     │
├─────────────────────────────────────────────────────────┤
│  业务层（Service）                                      │
├─────────────────────────────────────────────────────────┤
│  数据访问层（Mapper/MyBatis-Plus）                      │
├─────────────────────────────────────────────────────────┤
│  MySQL 8.0 数据库                                       │
└─────────────────────────────────────────────────────────┘
```

## 三、后端分层架构

### 3.1 分层架构设计

本项目采用标准的 **三层架构**（Controller-Service-Mapper），层次清晰，职责分明。

```
┌─────────────────────────────────────────────┐
│       Controller层（控制器层）              │
│  - 接收HTTP请求                              │
│  - 参数校验                                  │
│  - 调用Service层处理业务                    │
│  - 返回统一响应格式                          │
└────────────────┬────────────────────────────┘
                 ↓
┌─────────────────────────────────────────────┐
│        Service层（业务层）                  │
│  - 业务逻辑处理                              │
│  - 事务管理                                  │
│  - 调用Mapper层访问数据                      │
│  - 业务规则校验                              │
└────────────────┬────────────────────────────┘
                 ↓
┌─────────────────────────────────────────────┐
│       Mapper层（数据访问层）                │
│  - 数据库CRUD操作                            │
│  - 基于MyBatis-Plus                         │
│  - SQL映射                                  │
└────────────────┬────────────────────────────┘
                 ↓
┌─────────────────────────────────────────────┐
│         MySQL 8.0 数据库                    │
└─────────────────────────────────────────────┘
```

### 3.2 各层职责说明

#### Controller层（控制器层）
- **职责**：接收HTTP请求，参数校验，调用Service层，返回响应
- **注解**：`@RestController`, `@RequestMapping`, `@GetMapping`, `@PostMapping`等
- **统一响应**：所有接口返回统一的响应格式

#### Service层（业务层）
- **职责**：业务逻辑处理，事务管理，数据组装
- **注解**：`@Service`, `@Transactional`
- **设计模式**：接口 + 实现类

#### Mapper层（数据访问层）
- **职责**：数据库CRUD操作，SQL映射
- **注解**：`@Mapper`, `@Select`, `@Insert`, `@Update`, `@Delete`
- **继承**：MyBatis-Plus的`BaseMapper<T>`

### 3.3 分层架构优势

1. **职责分离**：各层职责明确，降低耦合度
2. **易于维护**：修改某层不会影响其他层
3. **便于测试**：可以单独对每一层进行单元测试
4. **可扩展性强**：新增功能只需在对应层添加代码

## 四、数据流设计

### 4.1 请求处理流程

```
用户发起请求
    ↓
前端拦截器（添加JWT Token到请求头）
    ↓
后端控制器接收请求（Controller）
    ↓
参数校验（Validation）
    ↓
Spring Security过滤器链
    ├─ Token验证（JWT Filter）
    ├─ 权限检查（Role Filter）
    └─ 放行/拒绝
    ↓
Service层处理业务逻辑
    ├─ 事务管理
    ├─ 业务规则校验
    └─ 调用Mapper层
    ↓
Mapper层访问数据库
    ├─ SQL执行
    └─ 结果返回
    ↓
数据组装与封装
    ├─ 实体转换（Entity → VO）
    └─ 统一响应封装
    ↓
返回JSON响应给前端
    ↓
前端解析并渲染页面
```

### 4.2 统一响应格式

所有后端接口统一返回以下格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    // 实际数据
  }
}
```

**响应码定义**：
- `200`：操作成功
- `400`：参数错误
- `401`：未认证
- `403`：无权限
- `404`：资源不存在
- `500`：服务器错误

### 4.3 分页响应格式

分页查询返回以下格式：

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "records": [],
    "total": 100,
    "current": 1,
    "pageSize": 10,
    "pages": 10
  }
}
```

## 五、安全架构设计

### 5.1 认证架构

#### 5.1.1 JWT认证流程

```
1. 用户登录
   ├─ 前端提交用户名/密码
   ├─ 后端验证用户名/密码
   ├─ 验证成功，生成JWT Token
   └─ 返回Token给前端

2. 后续请求
   ├─ 前端在请求头携带Token（Authorization: Bearer {token}）
   ├─ 后端拦截器提取Token
   ├─ 验证Token有效性
   ├─ 解析Token获取用户信息
   └─ 放行请求进入Controller
```

#### 5.1.2 JWT Token结构

```json
{
  "header": {
    "alg": "HS256",
    "typ": "JWT"
  },
  "payload": {
    "userId": 1,
    "username": "admin",
    "role": "ADMIN",
    "exp": 1735689600
  },
  "signature": "..."
}
```

#### 5.1.3 Token配置

- **Token有效期**：30天
- **Token刷新**：暂不支持刷新（Token过期需重新登录）
- **存储方式**：前端存储在LocalStorage
- **传输方式**：HTTP请求头 `Authorization: Bearer {token}`

### 5.2 授权架构

#### 5.2.1 角色访问控制（RBAC）

基于角色的访问控制，三种角色的权限如下：

| 角色 | 权限描述 |
|------|----------|
| **管理员（ADMIN）** | 所有权限，包括用户管理、审核、数据统计等 |
| **商家（MERCHANT）** | 店铺管理、菜品管理、活动发布等 |
| **学生（STUDENT）** | 浏览、评价、收藏、互动等 |

#### 5.2.2 权限控制实现

```java
// 方法级权限控制
@PreAuthorize("hasRole('ADMIN')")
public Result<Void> deleteUser(Long userId) { }

@PreAuthorize("hasAnyRole('ADMIN', 'MERCHANT')")
public Result<Merchant> getMerchantInfo(Long merchantId) { }

@PreAuthorize("hasRole('STUDENT')")
public Result<Void> publishReview(ReviewDTO reviewDTO) { }
```

### 5.3 安全策略

#### 5.3.1 密码安全
- **加密算法**：BCrypt
- **加密强度**：10轮
- **存储方式**：数据库存储加密后的哈希值

#### 5.3.2 数据安全
- **SQL注入防护**：使用MyBatis-Plus参数化查询
- **XSS防护**：前端对用户输入进行转义
- **CSRF防护**：前后端分离架构天然防护CSRF

#### 5.3.3 接口安全
- **HTTPS**：生产环境使用HTTPS（本地开发可用HTTP）
- **敏感数据加密**：密码、Token等敏感信息不返回前端
- **请求频率限制**：防止暴力破解和DDoS攻击

## 八、跨域配置

### 8.1 后端跨域配置

```java
@Configuration
public class CorsConfig {
    @Bean
    public CorsFilter corsFilter() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowCredentials(true);
        config.addAllowedOriginPattern("*");
        config.addAllowedMethod("*");
        config.addAllowedHeader("*");
        config.setMaxAge(3600L);

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);
        return new CorsFilter(source);
    }
}
```

### 8.2 前端代理配置

前端通过Vite代理解决跨域问题，请求`/api`路径的接口会被代理到`http://localhost:8080`。

## 十、部署架构

### 10.1 本地运行环境

**开发环境要求**：
- JDK 17+
- Node.js 18+
- MySQL 8.0+
- Maven 3.6+

**运行步骤**：
1. 启动MySQL数据库，执行建表SQL
2. 配置`application.yml`中的数据库连接信息
3. 启动后端服务：`mvn spring-boot:run`
4. 启动前端服务：`npm run dev`
5. 访问前端：`http://localhost:5173`
6. 访问后端：`http://localhost:8080`

## 十一、技术选型说明

### 11.1 为什么选择SpringBoot？
- 快速开发，简化配置
- 生态完善，社区活跃
- 适合中小型项目
- 与MyBatis-Plus、Spring Security等集成良好

### 11.2 为什么选择MyBatis-Plus？
- 简化CRUD操作
- 内置分页、条件构造器
- 支持代码生成
- 无需编写复杂的XML

### 11.3 为什么选择React？
- 组件化开发，代码复用性高
- 虚拟DOM，性能优秀
- 生态丰富，组件库完善
- 适合大型应用开发

### 11.4 为什么选择JWT？
- 无状态，适合前后端分离
- 跨域支持良好
- 扩展性强，可携带自定义信息
- 不需要服务器存储Session

### 11.5 为什么选择本地文件存储？
- 实现简单，适合小规模项目
- 无需引入第三方云存储服务
- 降低项目复杂度
- 毕业设计演示足够

## 十二、总结

本系统采用前后端分离架构（B/S架构），后端基于SpringBoot 3.x，前端基于React 18.x，技术栈成熟稳定。

**架构特点**：
1. **分层清晰**：Controller-Service-Mapper三层架构
2. **模块独立**：10个后端模块，职责明确
3. **安全可靠**：JWT认证 + 角色权限控制
4. **易于扩展**：模块化设计，便于功能扩展
5. **文档完善**：Knife4j自动生成接口文档

**开发原则**：
- 遵循RESTful API设计规范
- 统一响应格式和错误处理
- 参数校验和异常处理
- 代码规范和注释完善

通过本架构设计，为后续的开发工作奠定了良好的基础。

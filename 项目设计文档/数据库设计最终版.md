## 三、表结构设计(15张表)

### 3.1 user - 用户基础表

```sql
CREATE TABLE `user` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `username` VARCHAR(32) NOT NULL COMMENT '登录用户名',
  `password_hash` VARCHAR(256) NOT NULL COMMENT '密码哈希(BCrypt)',
  `role` ENUM('STUDENT','MERCHANT','ADMIN') NOT NULL COMMENT '角色',
  `status` ENUM('ACTIVE','DISABLED') NOT NULL DEFAULT 'ACTIVE' COMMENT '状态',
  `creator_id` BIGINT UNSIGNED NULL COMMENT '创建者ID',
  `updater_id` BIGINT UNSIGNED NULL COMMENT '更新者ID',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_deleted` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '逻辑删除(0=未删,1=已删)',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户基础表';
```

**字段说明**:
- `id`: 主键,自增
- `username`: 登录用户名,唯一
- `password_hash`: 密码哈希值(BCrypt加密)
- `role`: 角色(STUDENT-学生,MERCHANT-商家,ADMIN-管理员)
- `status`: 状态(ACTIVE-正常,DISABLED-禁用)
- `creator_id`: 创建者ID
- `updater_id`: 更新者ID
- `create_time`: 创建时间
- `update_time`: 更新时间
- `is_deleted`: 逻辑删除标记

### 3.6 review - 评价表

```sql
CREATE TABLE `review` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `user_id` BIGINT UNSIGNED NOT NULL COMMENT '评价用户ID',
  `food_id` BIGINT UNSIGNED NOT NULL COMMENT '菜品ID',
  `merchant_id` BIGINT UNSIGNED NOT NULL COMMENT '商家ID',
  `rating` TINYINT UNSIGNED NOT NULL COMMENT '评分(1-5)',
  `content` TEXT NOT NULL COMMENT '评价内容',
  `like_count` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '点赞数',
  `dislike_count` INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '踩数',
  `audit_status` ENUM('PENDING','APPROVED','REJECTED') NOT NULL DEFAULT 'PENDING' COMMENT '审核状态',
  `audit_admin_id` BIGINT UNSIGNED NULL COMMENT '审核人ID',
  `audit_time` DATETIME NULL COMMENT '审核时间',
  `audit_reason` VARCHAR(256) NULL COMMENT '审核理由(驳回时填写)',
  `creator_id` BIGINT UNSIGNED NULL COMMENT '创建者ID',
  `updater_id` BIGINT UNSIGNED NULL COMMENT '更新者ID',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_deleted` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '逻辑删除(0=未删,1=已删)',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='评价表';
```

**字段说明**:
- `id`: 主键,自增
- `user_id`: 关联user表ID(评价用户)
- `food_id`: 关联food表ID(被评价菜品)
- `merchant_id`: 关联merchant表ID(冗余,便于查询)
- `rating`: 评分(1-5星)
- `content`: 评价内容
- `like_count`: 点赞数
- `dislike_count`: 踩数
- `audit_status`: 审核状态(PENDING-待审核,APPROVED-已通过,REJECTED-已驳回)
- `audit_admin_id`: 审核人ID(关联user表,ADMIN角色)
- `audit_time`: 审核时间
- `audit_reason`: 审核理由(驳回时填写)
- `creator_id`: 创建者ID
- `updater_id`: 更新者ID
- `create_time`: 创建时间
- `update_time`: 更新时间
- `is_deleted`: 逻辑删除标记

## 五、级联删除处理(代码层面)

```java

    List<Food> foods = foodMapper.selectByMerchantId(merchantId);
```

## 六、数据库设计规范

### 6.1 命名规范

1. **表名**: 小写+下划线分隔,使用名词复数形式
   - 示例: `user`, `user_profile`, `food`

2. **字段名**: 小写+下划线分隔
   - 示例: `user_id`, `create_time`, `is_deleted`

3. **索引名**:
   - 主键索引: `PRIMARY`
   - 唯一索引: `uk_字段名`
   - 普通索引: `idx_字段名`

### 6.2 字段规范

1. **主键**: 所有表都使用`id`字段作为主键,类型为`BIGINT UNSIGNED`,自增

2. **必选字段**: 每个表都必须包含以下4个字段
   - `creator_id`: 创建者ID
   - `updater_id`: 更新者ID
   - `create_time`: 创建时间
   - `update_time`: 更新时间

3. **逻辑删除**: 所有表都必须包含`is_deleted`字段
   - 类型: `TINYINT(1)`
   - 默认值: 0
   - 0表示未删除,1表示已删除

4. **字符串长度**: 使用2的n次方长度
   - VARCHAR(32): 短文本(用户名、昵称)
   - VARCHAR(64): 中等文本(名称、标题)
   - VARCHAR(256): 长文本(URL、地址)
   - TEXT: 超长文本(描述、内容)

5. **数值类型**:
   - `BIGINT UNSIGNED`: 主键、外键ID
   - `INT`: 排序、计数
   - `TINYINT`: 评分、状态
   - `DECIMAL(10,2)`: 价格
   - `DECIMAL(2,1)`: 评分

6. **时间类型**:
   - `DATETIME`: 创建时间、更新时间

7. **枚举类型**: 使用`ENUM`类型存储状态
   - 示例: `ENUM('ACTIVE','DISABLED')`

### 6.3 注释规范

1. **表注释**: 每个表都必须有注释,说明表的用途
   - 示例: `COMMENT='用户基础表'`

2. **字段注释**: 每个字段都必须有注释,说明字段用途
   - 示例: `COMMENT '主键ID'`

### 6.4 关联规范

1. **不使用外键**: 不使用`FOREIGN KEY`约束,在代码层面保证数据一致性

2. **关联方式**: 通过`xxx_id`字段关联其他表
   - 示例: `user_id`关联`user`表

3. **冗余设计**: 合理使用冗余字段,减少关联查询
   - 示例: `review`表冗余`merchant_id`,便于商家查询评价

### 6.5 索引规范

1. **主键索引**: 所有表的主键自动创建索引

2. **唯一索引**: 需要唯一约束的字段创建唯一索引
   - 示例: `username`字段创建唯一索引

3. **普通索引**: 根据查询需要创建索引
   - 示例: `review_reply`表的`idx_review_id`和`idx_merchant_id`
   - 示例: `review_tag_relation`表的`idx_review_id`和`idx_tag_id`

## 九、总结

本数据库设计遵循以下原则:

1. **多表少字段**: 每个表字段少,职责明确
2. **清晰明确**: 表关系清晰,字段含义明确
3. **无外键约束**: 不使用数据库外键,代码层面控制
4. **统一规范**: 遵循统一的命名、注释、字段规范
5. **逻辑删除**: 所有表使用逻辑删除,数据安全
6. **审计字段**: 所有表包含创建者、更新者、创建时间、更新时间
7. **支持标签**: 新增评价标签功能,支持用户快速选择评价维度
8. **支持回复**: 新增商家回复功能,增强商家与用户互动

通过以上设计,确保数据库结构清晰、易于维护、扩展性好,满足校园美食评价系统的所有功能需求。

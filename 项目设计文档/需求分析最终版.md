# 基于SpringBoot的大学生校内美食评价系统 - 需求分析文档

## 一、项目背景与目标

### 1.1 项目背景
大学生在校内食堂或餐饮店就餐时，缺乏一个统一的评价参考平台，难以了解菜品口味、服务质量等信息。同时，商家也难以了解学生的真实需求和反馈，无法及时改进菜品和服务。

### 1.2 项目目标
- 为学生提供菜品评价、参考和决策依据，提升就餐体验
- 为商家提供反馈渠道，了解用户需求，改进服务质量
- 为管理员提供监管和审核工具，维护平台秩序

### 1.3 核心价值
解决校园餐饮信息不对称问题，搭建学生、商家、管理员之间的沟通桥梁，构建良性互动的校园美食生态。

---

## 二、用户角色与需求

### 2.1 学生用户
**核心需求：**
- 注册登录系统，维护个人资料
- 浏览商家信息、菜品列表及用户评价
- 查看菜品价格、评分、评价内容，辅助就餐决策
- 对已体验的菜品发表评价（评分、文字、图片）
- 对评价进行点赞/踩互动
- 收藏喜欢的店铺和菜品，方便快速访问
- 查看系统公告和商家活动信息

**典型场景：**
- 学生想尝试新食堂，查看该食堂下所有店铺和菜品评价
- 学生发现某道菜很好吃，发布评价并上传图片
- 学生收藏了几个经常光顾的店铺，快速访问查看新品

### 2.2 商家用户
**核心需求：**
- 注册为商家账号，提交店铺信息等待审核
- 管理店铺基本信息（名称、地址、营业时间等）
- 管理菜品信息（名称、价格、图片、分类、上下架）
- 发布活动信息（如促销、新品试吃等），提交审核
- 查看用户对店铺菜品的评价反馈
- 管理店铺营业状态（正常营业/暂停营业）

**典型场景：**
- 商家新增菜品，填写菜品信息和价格，上传图片并上架
- 商家查看用户评价，了解菜品优缺点，改进服务
- 商家发布周末促销活动，等待管理员审核通过后展示

### 2.3 管理员用户
**核心需求：**
- 登录系统，执行管理操作
- 审核商家注册申请（通过/驳回）
- 审核商家活动申请（通过/驳回）
- 发布系统公告（如系统上线、活动通知等）
- 管理用户账号（禁用违规用户）
- 管理内容（隐藏违规评价、删除恶意内容）
- 查看系统数据统计（用户数、商家数、评价数等）

**典型场景：**
- 管理员审核新注册商家，检查资质后通过
- 管理员发现违规评价，将其设置为隐藏状态
- 管理员发布系统维护公告，通知所有用户

## 三、功能范围界定

### 3.1 MVP功能（必须实现）

#### 3.1.1 用户认证模块
- 用户注册（用户名+密码）
- 用户登录（密码加密存储）
- 角色分配（学生/商家/管理员）
- 个人资料维护（手机号、学号等信息）
- 状态管理（正常/禁用）

#### 3.1.2 商家管理模块
- 商家信息录入（店铺名称、地址、营业时间）
- 商家信息修改
- 商家审核流程（待审核→通过/驳回）
- 商家营业状态管理
- 商家信息展示列表

#### 3.1.3 菜品管理模块
- 菜品分类维护（早餐、快餐、奶茶等）
- 菜品信息录入（名称、价格、图片、分类）
- 菜品信息修改
- 菜品上下架管理
- 菜品列表展示（支持按商家、分类、名称搜索）

#### 3.1.4 评价系统模块
- 用户发表评价（评分1-5星、文字内容、可选图片）
- 评价列表展示（按菜品、时间排序）
- 评价审核机制（需管理员审核后可见）
- 评分统计（计算菜品平均评分）
- 评价点赞/踩互动
- 评价删除（用户删除自己的评价）

#### 3.1.5 收藏模块
- 收藏店铺（防止重复收藏）
- 收藏菜品（防止重复收藏）
- 收藏列表展示
- 取消收藏

#### 3.1.6 公告模块
- 管理员发布公告（标题、内容、发布时间）
- 公告列表展示
- 公告删除

### 3.2 扩展功能

#### 3.2.1 活动管理模块
- 商家发布活动（标题、内容、开始时间、结束时间）
- 活动审核流程（待审核→通过/驳回）
- 活动列表展示
- 活动删除

#### 3.2.2 地图展示模块
- 集成高德地图JS API
- 展示商家店铺位置（坐标X/Y）
- 地图标注与信息展示

#### 3.2.3 推荐模块
- 基于热度的推荐（高评分、高评价数的菜品）
- 基于分类的推荐（按菜品分类展示热门菜品）
- 首页推荐列表

#### 3.2.4 数据统计模块
- 简单列表展示（用户列表、商家列表、评价列表）
- 基础数据统计（用户总数、商家总数、菜品总数、评价总数）
- 数据导出（可选）

## 四、非功能性需求

### 4.1 性能要求
- 支持同时在线用户数：100-500人
- 页面响应时间：<2秒
- 数据量预期：
  - 用户数：<1000
  - 商家数：<100
  - 菜品数：<1000
  - 评价数：<5000

### 4.2 安全要求
- 用户密码使用BCrypt加密存储
- 基于JWT的认证授权机制
- 角色权限控制（不同角色访问不同功能模块）
- SQL注入防护（使用MyBatis-Plus参数化查询）
- XSS攻击防护
- 逻辑删除（数据安全，避免误删）

### 4.3 可用性要求
- 响应式设计（适配PC端）
- 直观易用的UI界面
- 友好的错误提示信息
- 完善的操作反馈（成功/失败提示）

### 4.4 可靠性要求
- 数据一致性（使用事务保证关键操作）
- 异常处理机制（全局异常捕获与友好提示）
- 日志记录（关键操作日志、错误日志）

### 4.5 可维护性要求
- 代码规范化（遵循阿里巴巴Java开发规范）
- 接口文档（使用Swagger/Knife4j）
- 注释完善（关键业务逻辑添加注释）

## 五、业务规则与约束

### 5.1 用户注册规则
- 用户名唯一，不可重复
- 密码长度6-20位，需包含字母和数字
- 角色由用户注册时选择或管理员分配
- 管理员账号由系统初始化或超级管理员创建

### 5.2 商家审核规则
- 商家注册后状态为"待审核"
- 管理员审核：通过或驳回（需填写驳回理由）
- 只有审核通过的商家才能发布菜品和活动
- 审核驳回后，商家可修改信息重新提交审核

### 5.3 菜品管理规则
- 菜品必须关联商家和分类
- 菜品价格必须大于0
- 菜品图片大小限制：不超过5MB
- 支持的图片格式：jpg、jpeg、png
- 菜品下架后用户端不可见

### 5.4 评价审核规则
- 用户发表评价后，状态默认为"待审核"
- 管理员审核：通过（可见）或驳回（隐藏）
- 审核通过的评价才对其他用户可见
- 用户只能对自己体验过的菜品发表评价（可选限制）

### 5.5 评价互动规则
- 用户对评价可点赞或踩（二选一）
- 同一用户对同一评价只能互动一次（唯一约束）
- 点赞/踩可撤销
- 点赞数和踩数实时统计

### 5.6 收藏规则
- 用户可收藏店铺或菜品
- 同一用户对同一店铺/菜品只能收藏一次（唯一约束）
- 收藏后可取消收藏

### 5.7 活动审核规则
- 商家发布活动后，状态默认为"待审核"
- 管理员审核：通过或驳回（需填写驳回理由）
- 活动有开始时间和结束时间，过期自动失效
- 只有审核通过的活动才对用户可见

### 5.8 删除规则
- 所有删除操作使用逻辑删除（设置is_deleted=1）
- 用户可删除自己的评价
- 商家可删除自己的店铺和菜品（级联删除关联评价）
- 管理员可删除所有内容（用户、商家、评价、活动等）
- 删除操作需要确认提示

### 5.9 内容审核规则
- 管理员可隐藏违规评价（不删除，仅设置不可见）
- 违规内容包括：敏感词汇、广告、恶意攻击等
- 隐藏的内容管理员可恢复可见

## 六、技术约束

### 6.1 技术栈约束
- 后端：SpringBoot 3.x + MyBatis-Plus 3.5.x + Spring Security + JWT
- 前端：React 18.x + Vite 5.x + Ant Design 5.x + Axios
- 数据库：MySQL 8.0
- JDK：OpenJDK 17
- 地图服务：高德地图 JS API 2.0

### 6.2 部署环境
- 本地运行即可（不部署到云服务器）
- 使用本地文件存储图片（不使用云存储）
- 数据库使用本地MySQL服务

### 6.3 开发约束
- 不考虑移动端适配（仅PC端）
- 不引入缓存（如Redis）
- 不引入消息队列
- 不使用分布式架构（单体应用）

### 9.1 技术风险
- **风险**：高德地图API集成复杂度超出预期
- **应对**：提前调研API文档，准备降级方案（仅显示坐标文字）

- **风险**：功能开发时间不足

### 9.3 数据风险

## 十、总结

本项目定位为中级难度，覆盖校内美食评价的核心场景，功能完整且实用。采用主流技术栈，具有良好的可扩展性。项目分为5个阶段开发，预计9周完成，涵盖需求分析、系统设计、编码实现、测试优化和文档完善全流程。

通过本项目的开发，将全面掌握SpringBoot前后端分离开发、数据库设计、权限控制、第三方API集成等核心技术，为毕业设计和后续工作奠定坚实基础。
